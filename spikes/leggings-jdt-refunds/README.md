## What is deliberately changed in fixture copies

- Current packaged Boots: remove only the old **JDT refund mixin configuration**;
  keep its credit component, creation/installation policies and actual
  `JustDireRefundCompatibility.route`/capture/completion unchanged. The candidate
  calls that real route. Update only its MA guard's final boundary proof.
- Current packaged Leggings: update only its MA guard to use the same audited
  shared boundary, retaining its own capture/arm/consumed/completion proof and
  actual augment delivery. No JDT credit support is added to production.
- The fixture owns one candidate shrink observer, exact-item callback dispatch,
  generated copies of the existing bounded bytecode proof and a disposable
  Leggings credit/receipt witness. Its component uses `leggings_skeleton_test`,
  **not** the proposed production component identity.

The generated guard copies live under `build/generated`, not this source tree.
Generation deliberately checks expected source shapes. It is research scaffolding
to demonstrate a small migration, not a maintained source-rewriting build system.

The Leggings factory/paid-menu helpers explicitly call witness credit creation
and installation boundaries. They prove conservation around real outputs/payment,
**not** complete production lifecycle integration. Real save/recovery, all five
families/tier eligibility, dormant/absent credit preservation and maintained unit
coverage belong to implementation.

MA and Cucumber are staged even when JDT is absent. All optional artifacts come
from the existing shared pinned downloader/cache. No indev or release-graph
discovery is involved. Unknown wrappers refuse refunds and retain ordinary wear;
the proof admits only known routers or audited straight-line forwarding within
three wrapper layers. The joint acceptance includes shared + legacy MA + one
forwarder, not arbitrary-depth wrapper chains.

Retire this entire directory, the opt-in Gradle apply and reflective fixture
entry when focused maintained production tests supersede it. Do not keep the
generation/fixture-JAR rewrites as production infrastructure.
